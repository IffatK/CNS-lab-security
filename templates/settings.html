Message transport protection

Protection is controlled by the sender. When enabled, the browser encrypts the message using ElGamal key encapsulation and AES-256-GCM, and the attacker relay cannot inspect or edit it. When disabled, the message enters the readable lab relay even if the recipient has protection enabled. A protected recipient receives the relay IP and a tamper report if the message was changed. If both accounts are unprotected, the recipient receives edited text without a specific tamper notice.

How the protection flow works

01 · BrowserGenerates a one-time AES-256 key and encrypts the message using AES-GCM.
02 · ElGamalWraps the AES key with the server's public ElGamal key.
03 · NetworkOnly ciphertext and wrapped-key values cross the trusted HTTPS connection.
04 · ServerUnwraps and authenticates the message, then stores it with the app's existing AES-GCM + Ed25519 envelope.

Open this page and Compose using the same server hostname, port, and protocol. The app reports the active scheme and host in diagnostics.
